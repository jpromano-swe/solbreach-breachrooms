# Root + Impact

## Description

The `reopen_receipt` instruction can reopen an archived receipt at the same PDA address because the receipt PDA uses stable seeds and `init_if_needed`.

The receipt address is derived from only the task address and worker address:

```rust
seeds = [b"receipt", task.key().as_ref(), worker.key().as_ref()]
After a receipt is archived, the same worker can call reopen_receipt again with the same task and worker. The instruction rewrites the existing receipt back to Open and updates its generation, without requiring a one-way lifecycle transition or a fresh PDA namespace.
This allows a previously archived receipt to become active again at the same address.
Root Cause
reopen_receipt uses init_if_needed with stable seeds, then writes active receipt state regardless of the receipt’s previous lifecycle state.
The vulnerable account constraint is:
#[account(
    init_if_needed,
    payer = worker,
    space = 8 + Receipt::INIT_SPACE,
    seeds = [b"receipt", task.key().as_ref(), worker.key().as_ref()],
    bump
)]
pub receipt: Account<'info, Receipt>,
The vulnerable state rewrite is:
receipt.task = ctx.accounts.task.key();
receipt.worker = ctx.accounts.worker.key();
receipt.amount = ctx.accounts.task.amount;
receipt.generation = ctx.accounts.task.generation + 1;
receipt.status = ReceiptStatus::Open;
receipt.bump = ctx.bumps.receipt;
There is no guard preventing ReceiptStatus::Archived from being changed back to ReceiptStatus::Open.
Risk
Likelihood:
- This occurs whenever a worker calls reopen_receipt after their receipt has already been archived.
- The PDA address is deterministic for the same task and worker, so the same receipt account is reused instead of creating a new lifecycle-specific receipt.
Impact:
- Archived receipt state can become active again, breaking the expected finality of archived records.
- Any later logic that trusts an Open receipt can process stale or previously completed receipt state as active again.
Proof of Concept
// 1. A worker has a receipt derived from:
//    [b"receipt", task.key().as_ref(), worker.key().as_ref()]
//
// 2. The worker archives the receipt.
receipt.status = ReceiptStatus::Archived;

// 3. The worker calls reopen_receipt with the same task and worker.
//
// 4. Because init_if_needed accepts the existing PDA, the same receipt
//    account is reused.
//
// 5. The instruction rewrites the archived receipt back to Open.
receipt.task = task.key();
receipt.worker = worker.key();
receipt.amount = task.amount;
receipt.generation = task.generation + 1;
receipt.status = ReceiptStatus::Open;
Recommended Mitigation
// Do not reuse the same receipt PDA for a new lifecycle.
// Include a lifecycle generation or unique receipt id in the PDA seeds.

#[account(
    init,
    payer = worker,
    space = 8 + Receipt::INIT_SPACE,
    seeds = [
        b"receipt",
        task.key().as_ref(),
        worker.key().as_ref(),
        &next_generation.to_le_bytes(),
    ],
    bump
)]
pub receipt: Account<'info, Receipt>,
Also reject attempts to reopen archived receipts in place:
require!(
    receipt.status != ReceiptStatus::Archived,
    BreachRoomError::InvalidStatus
);
```
